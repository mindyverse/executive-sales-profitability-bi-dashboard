Business questions

What I wanted to understand.

  • Which departments and product categories contribute the most sales?
  • Which stores have stronger basket and sales activity?
  • How does performance move across retail weeks?
  • Where is discount pressure highest?
  • Which products may need a closer promotion review?
  • How should household data be interpreted when demographics are incomplete?
Build summary

How I put it together.

  • Loaded the raw grocery files into PostgreSQL.
  • Created raw, reference and analytics schemas.
  • Prepared SQL views for Power BI instead of using only raw CSV files.
  • Built a star-schema-style Power BI model.
  • Created DAX measures for sales, baskets, discounts and estimated margin.
  • Validated the main dashboard numbers against SQL checks.
Methodology

Careful wording mattered in this project.

I wanted the dashboard to be useful, but also honest about what the source data can and cannot support.

Estimated margin

The dataset includes sales and discounts, but it does not include actual product cost. Because of that, I used documented department-level assumptions to calculate estimated gross margin. It should be read as a comparison measure, not exact accounting profit.

Household data

Household demographic information is only available for part of the dataset. Missing demographic values were kept as UNKNOWN instead of removing valid sales transactions.

What I learned

This project helped me connect SQL, Power BI and business thinking.

I practised preparing data, checking quality, building a model, validating measures and presenting the results clearly. The softer page design is only the presentation layer; the main focus is still the analysis and the methodology behind it.
